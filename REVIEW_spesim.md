# spesim package review (teaching + method-testing focus)

Date: 2026-02-11  
Package site: https://ajsmit.github.io/spesim/  
Repo: https://github.com/ajsmit/spesim  
Version reviewed: **0.3.3** (per NEWS/site)

This document is a full, end-to-end review of **spesim** as a teaching and
method-testing package for spatially structured ecological communities.

---

## Executive summary

**spesim’s core strengths** are (i) a coherent “simulate → sample → analyse”
pipeline in *irregular domains*, (ii) excellent teaching ergonomics (init files,
clear vignettes, stable API guidance), and (iii) good alignment with canonical
community-ecology diagnostics.

**The main weaknesses** are typical of a deliberately lightweight simulator: some
models are heuristic rather than mechanistic; the domain/units are synthetic by
default; and several outputs can be misinterpreted as “process inference” unless
users read the model card.

**The 0.3.3 audit layer** (nearest-neighbour diagnostics, filtering checks,
sampling rejection/exclusion summaries) is a strong step toward turning spesim
into a “tutor that audits the user’s conceptual model”.

---

## 1) What spesim does well

### 1.1 Coherent pipeline for teaching *and* method testing
- The workflow is conceptually clean and matches how students think:
  1) generate a domain, 2) generate a heterogeneous community, 3) place quadrats
  (field-design analogues), 4) compute site × species and common summaries.
- `spesim_run()` provides a teaching-friendly entry point while leaving lower-
  level knobs accessible.

### 1.2 Sampling designs in irregular polygons are a differentiator
- Having **random / tiled / systematic / transect / Voronoi** schemes in one
  package, for **irregular domains**, is unusually practical.
- 0.3.3’s `placement_audit` attachment is exactly what method-testing needs:
  it surfaces boundary rejection/exclusion that otherwise stays hidden.

### 1.3 Documentation has strong “instructor ergonomics”
- The addition of **Start here** + the **model card** + **validation** vignettes
  improves discoverability and expectation-setting.
- The **public API / stability guide** is unusually mature for an early version.

### 1.4 Outputs align with common ecological questions
- Rank–abundance, occupancy–abundance, SAR, distance–decay, rarefaction are
  exactly the outputs most people want when learning how sampling interacts with
  spatial heterogeneity.
- Human-readable report is pedagogically valuable: it encourages narrative
  interpretation rather than black-box plotting.

### 1.5 The “audit” layer is directionally excellent
- `spesim_audit()` provides quick, approximate checks that answer:
  *“Did I actually get clustering?”*, *“Is filtering visible?”*,
  *“How much did the boundary constrain my design?”*
- The report’s **Conceptual audit** section is the right integration point.

## 2) Where the weaknesses are

### 2.1 Some core models are heuristic vs mechanistic
This is a design choice (lightweight, teachable), but it implies:
- Parameters do not generally map to biological rates/processes.
- Spatial patterns may be “consistent with” a process without being generated by
  a canonical process model (depending on settings).

The model card helps, but users can still over-interpret if they skip it.

### 2.2 Domain units / CRS and interpretability
- The default domain is synthetic and unitless (now documented).
- Gradients are rescaled to familiar units (°C, m, mm), which is pedagogically
  helpful but can mislead users into thinking they are simulating real-world
  geography unless they supply a real CRS/extent.

### 2.3 Audit diagnostics are useful but still approximate
- NN ratio vs CSR is a good lightweight diagnostic, but it is not a substitute
  for edge-corrected Ripley K or pair-correlation functions in irregular windows.
- Filtering audit is based on quadrat mean environments and abundance; it can be
  confounded by small sample sizes, sparse species, or strong interactions.

### 2.4 Scalability / performance
- Some steps (e.g., repeated intersections, report per-quadrat summaries) can
  become slow for very large N or high-resolution grids.
- This is fine for teaching, but method-testing may push sizes upward.

## 3) What it gets wrong (or risks getting wrong)

### 3.1 Risk: “named process” ≠ realised regime
Even with the audit layer, the package still risks a common teaching failure:
users select a named process (e.g., “Strauss”) and assume the realised pattern is
inhibited, when parameters may produce weak effects in practice.

0.3.3 mitigates this, but a stronger regime-classification framework would help
(see Recommendations).

### 3.2 The audit signals are not yet formalised as pass/fail thresholds
Right now, audits are descriptive (“CSR-like”, “weak signal”). In teaching,
people often want a red/amber/green judgement aligned with the conceptual model.

### 3.3 Sampling “inclusion probabilities” are only partially represented
- Boundary rejection/exclusion is reported (good).
- But inclusion probability is scheme-dependent and can be subtle:
  - systematic: grid-centre filtering,
  - tiled: tiling candidates,
  - transect: safe-area shrinkage and intersection geometry,
  - voronoi: suitability criterion + seed density.

The current audits provide the raw ingredients, but not yet a unified statement
like “effective sampling frame shrank by X%” or “edge-loss is severe”.

## 4) Recommendations (numbered for implementation tracking)

### R1. Add a **regime classification summary** with explicit thresholds  ✅ (implemented in v0.3.4-dev)
Add a small helper (or extend `spesim_audit()`) that converts the audit metrics
into a teaching-friendly judgement:
- Example: `spesim_regime(res)` → list with green/amber/red grades + reasons for
  spatial, filtering, and sampling constraints.

Implementation idea:
- spatial: use NN ratio bands (e.g., <0.85 clustered, 0.85–1.15 CSR-ish, >1.15 inhibited)
  and require minimum n.
- filtering: require rho > 0.2 and slope < 0 with minimum occupied sites.
- sampling: boundary exclusion > 50% triggers amber/red.

### R2. Add an **edge-corrected option** when spatstat is available ✅ (implemented in v0.3.5-dev)
Provide optional spatstat-based checks that can be turned on via an argument:
- `spesim_audit(res, diagnostics = c("nn", "spatstat"))`
- If spatstat is installed:
  - convert domain to `owin` (proper polygon window),
  - compute K/L and pcf summaries for selected species.

### R3. Standardise and document the `placement_audit` schema ✅ (implemented in v0.3.6-dev)
Right now `placement_audit` is scheme-dependent (reasonable), but you’ll get
better downstream tooling if you standardise keys.

Implemented changes:
- placement functions now attach audits via a shared helper and a permissive validator.
- audits always include: `scheme`, `n_requested`, `n_returned`.
- schemes include additional standard keys where applicable (candidates, attempts, safe-area fraction, etc.).

### R4. Add **effective sampling frame** reporting (area-based)
For each sampling scheme, report an area-based summary that captures the
boundary constraint:
- random: estimate accessible area as the domain eroded by half diagonal of
  quadrat, and report its fraction of original.
- transect: report `area(safe_domain)/area(domain)`.
- tiled/systematic: report fraction of candidate grid-centres (or cells)
  retained.

This provides a single interpretable number: *“your sampling frame shrank to 62%
  of the domain due to boundary exclusion.”*

### R5. Add a **filtering sanity plot helper**
Create a small plotting utility that overlays expected vs realised filtering:
- For each gradient species:
  - plot abundance vs environment,
  - show vertical line at configured optimum (in natural units),
  - show tolerance band.

This would pair naturally with `audit_environmental_filtering()`.

### R6. Extend audit to report **per-species occupied-quadrat counts**
Filtering checks can be unstable when the species is rare. Add:
- occupancy in quadrats (count of sites with abundance>0)
- warn when occupancy is below a threshold (e.g., <5).

### R7. Make the report’s “Conceptual audit” reproducible and configurable
- Keep current defaults (lightweight).
- Add `generate_full_report(..., include_audit = TRUE, audit_top_n = 6)`.

### R8. Provide a single “method-testing bundle” function
Consider a convenience function:
- `spesim_method_test(P, ...)` that returns:
  - res, audit, plus a small list of standard plots.

This reduces the “glue code” instructors write repeatedly.

### R9. Add at least one vignette explicitly about **method testing**
A short article that demonstrates:
- compare sampling schemes under the same underlying truth,
- compare inferred beta diversity / distance–decay across designs,
- show how audits change your interpretation.

### R10. Performance notes: document safe upper bounds for teaching
Add a small “performance” section (or vignette appendix) giving rules of thumb:
- N_individuals and grid resolution ranges that keep runs interactive.

## 5) Other packages with overlapping functionality

No single package matches spesim’s exact combination (irregular domains +
quadrat design suite + built-in classic panels + teaching report), but several
cover major components.

### Closest conceptual neighbour in R
- **mobsim**: community simulation with SAD + spatial patterns + sampling and
  biodiversity responses. Likely the nearest “same idea” for many users.

### Point processes / spatial diagnostics (R)
- **spatstat** (geom/random/explore): gold-standard simulation + inference +
  diagnostics (K, L, pcf, edge correction, irregular windows).

### Community ecology analyses (R)
- **vegan**: diversity indices, dissimilarities, SAR (`specaccum`), rarefaction.
- **iNEXT / iNEXT.3D**: rarefaction/extrapolation focused on inference.
- **betapart**: beta diversity partitioning (turnover/nestedness).
- **adespatial**: spatial multivariate methods and related diagnostics.

### Landscape / gradient simulation (R)
- **NLMR** + **landscapetools**: neutral landscapes / synthetic surfaces
  (then you add community simulation/sampling yourself).

### Outside R (partial overlap)
- **Python scikit-bio**: community dissimilarities and diversity tooling (not a
  spatial simulator).
- More mechanistic ecological simulators exist (individual-based / metacommunity
  models), but they are typically far more complex than spesim’s teaching-first
  design.
